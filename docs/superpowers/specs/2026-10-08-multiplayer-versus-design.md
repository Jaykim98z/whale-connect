# 멀티플레이 대전 모드 설계

작성일: 2026-10-08

## 목표

친구 2~8명이 방 코드로 모여, 같은 보드를 각자 풀며 점수를 겨룬다. 결과는 그 방 안에서만 보여주고 저장하지 않는다.

## 대전 규칙

프로토타입으로 직접 플레이해 보고 확정한 값이다. `src/game/versus.ts`에 모은다.

| 항목 | 값 |
|---|---|
| 보드 | 10 × 18, 장애물 12개, 카드 168장(84쌍) |
| 캐릭터 | 멤버 15 + 팬캐릭 6 |
| 제한 시간 | 120초 고정 (전원 같은 시각에 시작·종료) |
| 점수 | 매칭 +10. 콤보 없음 |
| 클리어 | +100점, 잔여 초 × 10점. 클리어한 사람은 순위표를 보며 대기 |
| 시간추가 아이템 | 없음 |
| 셔플 아이템 | 3쌍 |
| 장애물 부수기 | 시작 시 2회. 장애물을 클릭하면 사용 |
| 일시정지 | 없음. 나가면 기권 |
| 동점 | 그 점수에 먼저 도달한 사람이 위 |

모두 같은 시드로 시작하므로 초기 보드는 같다. 셔플 결과는 각자의 진행 상태에 따라 달라진다.

120초 안에 84쌍을 모두 지우기는 어렵다. 클리어 보너스는 규칙으로 남겨 두지만 대부분의 판은 지운 쌍 수로 순위가 갈린다.

## 방 흐름

1. 타이틀의 "멀티플레이" 버튼 → 닉네임(12자) 또는 SOOP 아이디 중 하나를 골라 입력 → 방 만들기 또는 코드로 입장.
   SOOP 아이디를 고르면 SOOP 닉네임과 프로필 사진으로 표시된다.
2. 대기실: 6자리 방 코드, 초대 링크(`?room=CODE`) 복사, 참가자 목록. 방장만 시작할 수 있고 2명 이상일 때 활성화된다.
3. 시작: 방장이 시드와 시작 시각(서버 시각 + 4초)을 기록 → 전원에게 3·2·1 카운트다운 → 동시 출발.
4. 플레이: 보드 옆에 실시간 순위표(순위·닉네임·점수·진행률 막대). 순위가 바뀌면 행이 미끄러지듯 이동한다.
5. 결과: 자기 판이 끝나면 순위표가 결과 창으로 뜬다. 전원이 끝나면 방장이 "한 판 더"로 대기실에 돌아간다.

## 기술 구조

실시간 통신은 Firebase Realtime Database를 쓴다. 서버 코드는 없고, 클라이언트가 방 데이터를 쓰고 구독한다.

### 데이터

```
rooms/{code}
  meta:    { hostId, status: 'lobby' | 'playing', seed, startAt, round, createdAt }
  players/{playerId}:
           { name, soopId?, profileImage?, joinedAt, connected,
             score, progress, scoredAt, finished }
```

- `playerId`는 입장할 때마다 새로 만드는 임의 문자열이다.
- 점수는 매칭이 끝날 때마다 자기 `players/{playerId}`에 쓴다(판당 최대 약 90회).
- `scoredAt`은 서버 시각이며 동점 순위에 쓴다.
- 판을 시작할 때 방장이 한 번의 갱신으로 `meta`와 전원의 점수 필드를 초기화한다.

### 시각 동기화

`.info/serverTimeOffset`으로 서버 시각을 추정한다. 각 클라이언트는 `startAt`에 게임을 시작하고, 제한 시간을 `startAt + 120초 − 현재 서버 시각`으로 잡아 종료 시각을 맞춘다.

### 접속 끊김

- 대기실: `onDisconnect`로 자기 플레이어 항목을 지운다.
- 플레이 중: `onDisconnect`로 `connected: false`만 기록한다. 순위표에 "연결 끊김"으로 표시하고 점수는 유지한다.
- 대기실로 돌아갈 때 방장이 끊긴 플레이어 항목을 지운다.
- 방장이 없거나 끊기면, 접속 중인 사람 가운데 가장 먼저 들어온 사람이 트랜잭션으로 방장이 된다.
- 진행 중인 방에는 입장할 수 없다. 새로고침하면 방에서 나간 것으로 처리한다.

### 보안 규칙 (`database.rules.json`)

로그인이 없으므로 방 코드를 아는 사람은 그 방을 읽고 쓸 수 있다. 규칙은 다음만 막는다.

- `rooms` 전체 목록 조회 (방 코드를 모르면 접근 불가)
- 정해진 필드 외의 쓰기, 형식·길이·범위를 벗어난 값

점수 조작은 막지 않는다(친구끼리, 저장 없음으로 합의).

### 알려진 한계

- 방은 마지막 사람이 "방 나가기"로 나갈 때만 지워진다. 탭을 닫거나 끊겨서 남은 방은 `cleanupRooms` 예약 함수(매일 05:00 KST)가 만든 지 24시간이 지나면 지운다.
- 모바일 세로 화면에서는 18열 보드의 카드가 매우 작다. 멀티는 데스크톱 기준으로 만든다.

## 코드 구성

| 파일 | 역할 |
|---|---|
| `src/game/versus.ts` | 대전 규칙 상수, 카드 수 분배, 진행률 계산 |
| `src/game/gameReducer.ts` | `versus` 모드 추가: 큰 보드, 콤보 없음, 장애물 부수기, 일시정지 불가, 단판 클리어 |
| `src/game/roomLogic.ts` | 순수 함수: 방 코드 생성·정규화, 순위 계산, 다음 방장 선정, 판 종료 판정 |
| `src/services/room.ts` | Realtime Database 입출력: 방 생성·입장·퇴장, 구독, 판 시작, 점수 보고, 접속 상태 |
| `src/hooks/useRoom.ts` | 방 구독, 접속 상태 등록, 방장 승계 |
| `src/components/Multi/` | `Multi`(화면 전환), `MultiEntry`(입장), `Lobby`(대기실), `VersusGame`(플레이), `Leaderboard`(순위표) |
| `src/components/Hud.tsx` | 스테이지·일시정지·랭킹·새 게임 버튼을 선택 표시로 변경, 진행률·부수기 표시 |

싱글 게임의 규칙과 화면은 바뀌지 않는다.

## 테스트

- `gameReducer.test.ts`: 대전 모드 시작 상태, 콤보 없음, 장애물 부수기, 일시정지 무시, 클리어 보너스.
- `roomLogic.test.ts`: 방 코드, 순위(동점 포함), 방장 선정, 판 종료 판정.
- 실시간 동작은 Database 에뮬레이터에 브라우저 탭 두 개를 붙여 확인한다.

## 배포

Realtime Database 인스턴스를 만들고 `VITE_FIREBASE_DATABASE_URL`을 `.env`에 넣어야 한다. 값이 없으면 멀티플레이 버튼을 숨긴다.

배포 순서는 `database` 규칙 → `hosting`이다. 규칙이 먼저 올라가 있어야 새 클라이언트가 방을 만들 수 있다.
